# ผลแก้บัคและทดสอบซ้ำ — 2 ตุลาคม 2569

อ้างอิงหมายเลขจาก QA_REPORT_2026-10-02.md ซึ่งเป็นผล **ก่อนแก้**

## สถานะล่าสุด — ใช้งานฐานข้อมูลรุ่นใหม่แล้ว

ผู้ใช้อนุญาตปิดสถานะห้องเดิมแล้ว ปิดครบ 56 ห้องโดยไม่ลบข้อมูล และยืนยันไม่มีห้องเปิดอยู่
ใช้ migration `secure_rooms` บน Supabase หลักสำเร็จแล้ว

- `verify_rooms.sql` ผ่านทั้งหมดภายใต้ role anon แล้ว ROLLBACK ข้อมูลทดสอบ
- ทดสอบผ่าน Godot สองโปรเซสจริง: สร้างห้อง, กรอกรหัสผิด/ถูกผ่าน dialog,
  จั่วทั้งสองฝั่ง, sync, reconnect และ Exit Lobby ของ Guest/Host ผ่าน
- ยืนยันฐานข้อมูล: หลัง reconnect ยัง playing, Guest ออกกลับ waiting พร้อมล้าง guest/token,
  Host ออกเป็น closed และไม่มีรหัสผ่าน plaintext
- หลักฐานเพิ่ม: [live_room_checks.json](qa/2026-10-02-fixes/live_room_checks.json) ผ่าน 7/7
- ลบห้อง QA รอบสุดท้ายแล้ว ตรวจซ้ำเหลือ 0 แถว; ไม่มีห้องเปิดและไม่มีรหัสผ่าน plaintext
- ข้อ 9 และส่วนฐานข้อมูลของข้อ 10 ที่เคยค้าง ได้ทดสอบผ่านแล้ว
- การทดสอบทั้งหมดเป็น headless; ยังไม่ได้รับรอง UI/เมาส์จริงหรือ stress test

Advisor เตือนการเปิด SECURITY DEFINER RPC 4 ฟังก์ชันให้ anon/authenticated (8 findings)
เป็น public API ที่ตั้งใจให้เกมไม่ต้องสมัครบัญชีเรียกได้ โดยจำกัดการอ่านและตรวจรหัส/token
ตรวจคำเตือนแล้ว ไม่ได้ปิดการเข้าถึงที่เกมต้องใช้ ดู
[anon RPC advisory](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable)
และ [authenticated RPC advisory](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable)

## หลักฐานหลังแก้

- Local: `REGRESSION_RESULT 13/13`, Godot exit 0; ไม่พบ SCRIPT ERROR/ERROR ในรอบสุดท้าย
- Online: `ONLINE_RESULT 14/14`; สอง Godot processes เชื่อม Supabase Realtime จริง
- Online ตรวจ duplicate, draw order/count, Guest dice, counter/face/raw data, zone count,
  reconnect, Guest draw หลัง sync, กลับ local และ engine errors
- ผล assertions: [local_checks.json](qa/2026-10-02-fixes/local_checks.json), [online_checks.json](qa/2026-10-02-fixes/online_checks.json)
- วิธีรันซ้ำ: [tests/README.md](../tests/README.md)

รอบแก้นี้ใช้ช่อง Realtime ชั่วคราวที่ไม่มีแถว rooms จึง **ไม่ได้** ทดสอบสร้าง/เข้าห้อง
ผ่าน RPC ฐานข้อมูลรุ่นใหม่ การทดสอบ Exit ใน transport suite ข้ามเฉพาะการเขียน DB
และทดสอบการ disconnect/reset/เปลี่ยน scene จริง ต้องทดสอบ lifecycle DB เพิ่มหลัง migration

การทดสอบเป็น headless เรียกฟังก์ชัน/สัญญาณจริง ยังไม่ใช่การตรวจ UI ด้วยเมาส์จริง,
stress test, packet loss, หรือเกม export จึงไม่รับรองว่าไม่มีบัคอื่นเหลือ

## งานที่เหลือ: Supabase

ผู้ใช้อนุญาตแล้วให้ใช้ `supabase/migrations/20261002_secure_rooms.sql`
**หลังตรวจ schema และเมื่อไม่มีห้องจริงกำลังเล่น** ไม่ต้องขออนุญาตขอบเขตเดิมซ้ำ
ณ เวลาบันทึกยังไม่มีช่องทาง SQL ที่เชื่อมต่อแล้ว จึงไม่ได้เปลี่ยน schema/ข้อมูลจริง

**ไคลเอนต์ที่แก้แล้วต้องใช้ migration ก่อนสร้างหรือเข้าห้องออนไลน์ได้**
ไม่ย้อนกลับไปใช้ direct REST ที่ข้ามรหัสผ่านได้เมื่อ RPC ยังไม่มี
Local และการตรวจ Realtime แบบ fixture ยังทำงานได้

ขั้นต่อไปหลังเชื่อมต่อ:

1. ตรวจ preflight.sql รวม schema/constraints/policies/grants และ pgcrypto schema
2. ยืนยันไม่มีห้องจริง waiting/playing และทบทวน SQL ให้ตรง schema ก่อนใช้
3. ใช้ migration และรัน verify_rooms.sql (ทดสอบแล้ว ROLLBACK)
4. ทดสอบสร้าง/รหัสผิด/รหัสถูก/ออก Guest/ออก Host ผ่าน UI callbacks กับห้อง QA ที่ได้รับอนุญาต
5. ลบเฉพาะห้อง QA และยืนยันไม่เหลือแถว รวม QA เก่าที่ลบไม่ได้ในรอบก่อน

ยังไม่ได้ push และเก็บการแก้ไขเดิมของผู้ใช้ไว้
